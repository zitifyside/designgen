# 1장. AI Design Generator 개요

## 1.1 시스템 정의

. 목적 : AI Design Generator 는 요건사항과 디자인 컨텍스트를 입력받아 System 이 AI Pipeline 을 통해 디자인 시스템 3종과 컨셉별 디자인 시안 5종(총 15종)을 자동 생성하고, Design Token 수정 시 시안에 실시간 반영하며, Figma·코드·MCP 까지 단일 Token 체계로 관통하는 Design System Infrastructure Platform 이다.
. 분류 : SaaS 형 디자인 인프라 서비스이다. 단순 시안 생성 도구가 아니라 디자인 시스템 인프라로 포지셔닝한다.

## 1.2 운영 범위

. 핵심 기능 : 디자인 시스템 자동 생성, 시안 자동 생성, Design Token 실시간 반영, Multi-Format Export(.fig·.png·.json·.css), Copy & Paste, 템플릿 마켓 운영, 팀 협업 지원을 포함한다.
. 부가 기능 : 프로젝트 관리, 사용자 관리, 결제·과금 관리, 감사 로그, 알림 센터, 도움말·FAQ, 피드백 채널을 포함한다.

## 1.3 Touch Point 구성

System 은 4종의 User Touch Point 를 통해 동일한 Core Platform 에 접근한다. 4종은 모두 단일 API Gateway 를 경유한다.

| Touch Point | 제공 시점 | 주요 대상 |
|---|---|---|
| Figma Plugin | v0.1.0 (Alpha) | 디자이너 (Figma 사용자) |
| Web App | v0.5.0 (Beta) | PM·기획자·비디자이너 |
| Public API | v1.0.0 (정식) | 디자인 에이전시·노코드 플랫폼·외부 서비스 |
| MCP Server | v1.0.0 (정식) | 개발자 (Cursor·Claude Code·Windsurf 사용자) |

## 1.4 연동 시스템

. Anthropic Claude API : LLM 호출에 사용하는 외부 시스템이다. Input Analyzer·Concept Engine·Layout Engine 단계의 자연어 분석·콘셉트 도출·레이아웃 구조 생성에 사용한다.
단, Claude API 응답 Timeout 시 System 이 최대 3회 자동 재시도한다.

. Image Generation API : Stable Diffusion 또는 DALL-E 를 사용한다. Renderer 단계의 시안 이미지 생성에 사용한다.
단, Image Gen 실패 시 System 이 Token 기반 CSS 렌더링으로 대체 출력한다.

. Stripe : 결제·구독·환불을 처리하는 외부 시스템이다. checkout.session.completed·invoice.paid·subscription.updated 등 Webhook 으로 상태를 동기화한다.
단, Webhook 서명 검증 실패 시 System 이 401 을 반환하고 처리를 차단한다.

. Figma Plugin API : .fig Export 와 Figma Variables 동기화에 사용하는 외부 인터페이스이다.
단, .fig 직접 생성이 불가한 경우 System 이 SVG + 메타데이터 방식으로 대체한다.

. AWS S3 / GCS : 파일 저장소이다. 사용자 업로드 파일, 시안 썸네일, Export 파일을 저장한다. SSE-S3 또는 SSE-KMS 로 암호화한다.

. SendGrid 또는 AWS SES : 이메일 발송에 사용한다. 검증 메일·결제 알림·주간 요약·마케팅 메일을 발송한다.

. Sentry·Datadog : 에러 트래킹·APM 에 사용한다. 에러율 5% 초과 시 운영 담당자에게 알림이 발송된다.

# 2장. 핵심 용어 정의

## 2.1 디자인 시스템·Design Token

. 디자인 시스템 (Design System, DS) : Color·Typography·Spacing·Border·Shadow·Component 등 UI 전반의 시각적 규칙을 정의한 체계이다. 1개 프로젝트는 최대 3종의 DS 를 보유한다.
. Design Token : DS 의 최소 단위 값이다. W3C Design Tokens Community Group (DTCG) 2025.10 stable 표준 JSON 규격을 준수한다.
. 구분 기준 : 디자인 시스템은 Token 의 집합이며, Design Token 은 단일 값이다.

## 2.2 컨셉·시안

. 컨셉 (Concept) : DS 의 스타일 방향성을 정의하는 테마이다. 예: Modern Minimal, Bold Vibrant. 컨셉은 A·B·C 3종으로 라벨링된다.
. 시안 (Mockup) : DS 를 기반으로 System 이 생성한 실제 화면 레이아웃 결과물이다. 1개 컨셉은 5종의 시안을 보유한다.
. 컨셉 구별성 기준 : 3종 컨셉의 Primary Color Hue 차이가 60도 이상이어야 한다. 미달 시 System 이 Hue 를 강제 조정하여 재생성한다.
. 시안 다양성 기준 : 5종 시안 간 구조적 유사도가 70% 이하이어야 한다.

## 2.3 AI Pipeline 4단계

System 은 4단계 모듈의 순차 처리를 통해 DS 와 시안을 생성한다. 평균 2~3분이 소요된다.

| 단계 | 명칭 | 처리 주체 | 입력 | 출력 | 소요 시간 |
|---|---|---|---|---|---|
| 1 | Input Analyzer | LLM + Vision Model | 요건(텍스트·파일·이미지), 플랫폼 | 구조화된 요건 분석 JSON | 10~15초 |
| 2 | Concept Engine | LLM | 요건 분석 결과 | 3종 컨셉 정의 + W3C DTCG Token 세트 | 15~20초 |
| 3 | Layout Engine | LLM | Token + 요건 분석 결과 | 컨셉별 5종 레이아웃 구조 JSON | 30~45초 |
| 4 | Renderer | Image Gen + QA Validator | 레이아웃 + Token | 시안 이미지 + 편집 레이어 + 썸네일 | 60~90초 |

## 2.4 크레딧

. 정의 : AI Pipeline 추가 생성에 사용하는 종량제 사용권이다. 1 크레딧이 1회 생성에 대응한다.
. 충전 단가 : Pro $0.5/회, Team $0.3/회. 최소 충전 단위는 10회이다.
. 차감 시점 : AI Pipeline 실행 시작 시점에 1 크레딧이 차감된다. 차감 후 생성 취소 시 본 정책서 §5.5 가 적용된다.
. 유효기간 : 구매일로부터 1년이다. 유효기간 경과 시 자동 소멸하며 환불되지 않는다.

## 2.5 API Key·MCP Server

. API Key : Public API 및 MCP Server 접근용 인증 키이다. Pro·Team 등급에서 발급 가능하다.
. Key 표시 정책 : 발급 시 1회만 평문으로 표시하며, Server 는 해시값만 저장한다. 이후 재조회가 불가하다.
. MCP Server (Model Context Protocol Server) : Anthropic 이 정의한 표준 인터페이스를 통해 AI 코딩 도구(Cursor·Claude Code·Windsurf)에 Design Token 을 공급하는 서버이다.
. MCP Server 인증 : API Key 를 환경변수 `ADG_API_KEY` 에 설정하여 사용한다.

## 2.6 템플릿·팀

. 템플릿 (Template) : Pro+ 등급 사용자가 마켓에 등록·판매할 수 있는 DS 프리셋이다. 카테고리는 SaaS 대시보드·이커머스·모바일앱·랜딩페이지 4종이다.
. 템플릿 라이선스 : 구매자에게 비독점적·전 세계적·영구적 사용 라이선스를 부여한다. 재판매는 불가하다.
. 팀 : Team 등급 가입 시 자동 생성되는 협업 단위이다. 기본 5명 수용하며, 추가 시드는 1인당 월 $9 이다.
. 팀 역할 : Owner·Admin·Member 3종으로 구분한다. 상세는 §18.2 를 준용한다.

# 3장. 계정 생성 및 관리 정책

## 3.1 가입 경로

. 가입 방식 2종 : 이메일 회원가입, OAuth 2.0 소셜 로그인 (Google·Apple·GitHub).
. 동의 의무 : 가입 시 이용약관·개인정보처리방침 동의가 필수이다. 미동의 시 가입이 불가하다.
. 동의 이력 저장 : System 은 terms_accepted_at·terms_version 컬럼에 동의 시점과 약관 버전을 기록한다.
단, 약관 개정 시 System 이 재동의 모달을 노출하며, 재동의 거부 시 서비스 이용을 제한한다.

## 3.2 이메일 검증 정책

. 검증 토큰 유효기간 : 발송일로부터 24시간이다.
. 미검증 상태 제한 : 이메일 미검증 사용자는 AI 생성 기능(F-002·F-003) 이용이 불가하다.
. 재발송 : User 가 [재발송] 클릭 시 새 토큰이 발급되며 기존 토큰은 무효화된다.
. OAuth 가입자 : Provider 가 이메일 검증을 제공하는 경우 자동 검증된다. 추가 검증을 요구하지 않는다.

## 3.3 비밀번호 정책

. 길이 : 8자 이상 64자 이하
. 구성 요소 : 영문 대문자 1개 이상, 영문 소문자 1개 이상, 숫자 1개 이상, 특수문자 1개 이상을 포함한다.
. 저장 방식 : bcrypt 해시로 저장한다. 평문 저장이 불가하다.
. 변경 제한 : 직전 5회 비밀번호의 재사용이 불가하다.
. 변경 후 처리 : 비밀번호 변경 시 System 이 알림 메일을 발송한다.
단, 비밀번호 변경 후 전체 세션을 강제 로그아웃하며, 변경 직후 재로그인이 필요하다.

## 3.4 계정 잠금 정책

. 잠금 조건 : 비밀번호 오류 5회 연속 누적 시 System 이 계정을 30분간 자동 잠금 처리한다.
. 잠금 해제 절차 1 (자동) : 30분 경과 시 자동 해제된다.
. 잠금 해제 절차 2 (수동) : User 가 [비밀번호 재설정] 을 통해 즉시 해제 가능하다.
. 의심 활동 감지 : System 이 다중 IP·다중 디바이스 동시 로그인 시도를 감지한 경우 계정을 즉시 잠그고 User 에게 이메일 알림을 발송한다.

## 3.5 2단계 인증 정책

. 적용 대상 : Pro·Team 등급은 권장, Admin 은 필수이다.
. 방식 : TOTP (Time-based One-Time Password) 표준 사용. Google Authenticator·1Password 호환이다.
. 백업 코드 : 활성화 시 10개 1회용 백업 코드가 발급된다. 사용 시 즉시 무효화된다.
. 재발급 : 백업 코드 잔량이 3개 이하일 때 User 가 신규 발급 가능하며, 기존 코드는 즉시 무효화된다.
. 해제 절차 : 비밀번호 + TOTP 코드 동시 입력이 필요하다.
단, 백업 코드 분실 + TOTP 디바이스 분실 시 본인 확인(여권·운전면허 등) 후 운영 담당자가 수동 해제한다.

## 3.6 세션 관리 정책

. Access Token 유효기간 : 1시간
. Refresh Token 유효기간 : 30일. DB 에 저장되며 로그아웃 시 즉시 무효화한다.
. 동시 세션 수 : 등급별 제한이 없다. 단, User 가 [모든 세션 로그아웃] 으로 현재 외 전부를 종료 가능하다.
. 세션 정보 저장 : User-Agent·IP 주소·last_active_at 을 저장한다. User 가 [마이페이지 > 보안 > 세션 관리] 에서 조회 가능하다.

# 5장. AI Pipeline 생성 정책

## 5.1 월간 생성 한도

. Free : 월 3회
. Pro : 월 30회
. Team : 무제한
. 초기화 시점 : 매월 1일 00:00 KST 에 카운터가 0 으로 초기화된다.
. 미사용분 이월 : 이월되지 않는다. 사용하지 않은 횟수는 매월 1일 소멸한다.
. 추가 생성 : Free·Pro 는 크레딧 구매로 추가 생성이 가능하다.

## 5.2 동시 세션 제한

. 동시 생성 세션 : User 당 1개로 제한한다.
. 추가 시도 시 처리 : 기존 세션이 Completed·Failed·Cancelled 상태에 도달하기 전까지 신규 생성을 차단한다. Client 가 "현재 진행 중인 생성이 있습니다. 완료 후 다시 시도해주세요." 안내를 출력한다.
. 백그라운드 모드 : User 가 진행 중 [백그라운드] 클릭 시 다른 메뉴 이용이 가능하다. 완료 시점에 인앱 알림이 발송된다.

## 5.3 자동 재시도·Fallback

. Timeout 정의 : AI Provider API 응답이 30초를 초과하는 경우를 Timeout 으로 처리한다.
. 재시도 횟수 : 최대 3회. Exponential backoff (1초·2초·4초) 적용한다.
. 3회 실패 시 : 생성 Job 상태가 Failed 로 전이된다. Client 가 오류 메시지와 [다시 시도] 버튼을 출력한다.

| 실패 유형 | Fallback 처리 |
|---|---|
| AI API Timeout (3회 초과) | Failed 상태 전이 + User 알림 |
| 컨셉 구별성 미달 (Hue 차이 60도 미만) | 컨셉 C 의 Hue 강제 조정 후 재생성 |
| Token 참조 오류 (시안 내 미정의 Token 사용) | System 이 자동 보정 후 재렌더링 |
| Image Generation 실패 | Token 기반 CSS 렌더링으로 대체 출력 (이미지 품질 저하 안내) |

## 5.4 생성 우선순위

. 우선순위 큐 : System 은 부하 분산을 위해 Pro·Team 등급의 Job 을 Free 등급보다 우선 처리한다.
. 동일 등급 내 순서 : FIFO (선입선출).
. 긴급 대응 : Admin 이 특정 Job 의 우선순위를 수동 변경할 수 있다.

## 5.5 생성 취소 시 크레딧 처리

User 가 진행 중 생성을 취소한 경우, 진행률에 따른 환불 정책이 적용된다.

| 진행률 | 환불률 |
|---|---|
| 30% 미만 | 100% 환불 (전액) |
| 30% 이상 70% 미만 | 50% 환불 |
| 70% 이상 | 환불 없음 |

. System 오류로 인한 실패 : 자동 재시도 3회 후 Failed 상태 시 100% 환불한다.
. 환불 처리 시점 : 취소·실패 확정 시점에 credit_transactions 테이블에 refund 거래로 즉시 기록한다.

# 7장. 디자인 시스템·시안 정책

## 7.1 Design Token 수정 권한

| 등급 | 수정 가능 Token |
|---|---|
| Free | Color (Primary·Secondary·Neutral·Semantic) 만 |
| Pro·Team·Admin | 전체 Token (Color·Typography·Spacing·Border·Shadow·Components) |

. Free 등급 잠긴 영역 UI : 잠긴 Token 카테고리는 회색 배경 + 자물쇠 아이콘 + [Pro 업그레이드 안내] 툴팁으로 표시한다.
. 실시간 반영 : User 수정 후 500ms 이내 모든 시안에 반영한다. Server 동기화는 debounce 300ms 후 PATCH 요청으로 처리한다.
. 동시 수정 충돌 : Last-Write-Wins 정책 (v1.0). v2.0 에서 Operational Transform 도입을 검토한다.

## 7.2 컨셉·시안 저장

. 자동 저장 : Token 수정·시안 즐겨찾기 등 모든 변경은 즉시 영속화한다.
. 컨셉별 독립 관리 : A·B·C 컨셉은 각각 독립된 DS Token 세트를 보유한다. 한 컨셉의 수정은 다른 컨셉에 영향을 주지 않는다.
. 시안 단위 : 컨셉당 5종의 시안은 동일 DS Token 을 공유한다. Token 수정 시 5종 모두에 반영된다.

## 7.3 버전 히스토리·복원

. 버전 생성 시점 : 다음 이벤트 발생 시 System 이 자동으로 새 버전 스냅샷을 생성한다.
  - AI 생성 완료
  - User 가 [버전 저장] 명시적 클릭
  - 템플릿 프리셋 적용 직전 (백업 목적)
. 보존 정책 : 최대 50개 버전 보유. 초과 시 가장 오래된 버전부터 자동 삭제한다.
. 복원 처리 : User 가 [버전 복원] 클릭 시 System 이 신규 버전을 생성하여 해당 시점의 Token·시안으로 갱신한다. 기존 버전은 삭제하지 않는다.

# 12장. 저작권·라이선스

## 12.1 사용자 생성물의 저작권

. 사용 권한 : User 는 본인 생성물을 상업적·비상업적 목적으로 자유롭게 사용·수정·재배포할 수 있다.
. 분리 자산의 라이선스 : Token 외의 다음 자산은 별도 라이선스가 적용된다.
  - 표준 폰트 (Google Fonts 등) : 해당 폰트 라이선스
  - 표준 아이콘 라이브러리 : 해당 라이브러리 라이선스
  - User 가 입력한 참조 이미지 : 원저작자 귀속

## 12.2 회사의 사용 권리

. 처리 권리 : 회사는 User 가 생성한 데이터를 서비스 제공 목적(저장·전송·처리)으로만 사용한다.
. 마케팅·홍보 사용 : User 의 명시적 동의 없이 User 생성물을 마케팅·홍보 목적으로 사용하지 않는다.
. 마켓 등록 예외 : User 가 템플릿 마켓에 등록한 DS 는 회사의 마켓 운영 목적으로 노출·홍보될 수 있다.

## 12.3 AI 학습 미사용

. 원칙 : 회사는 User 가 입력한 요건사항·파일·생성된 DS·시안 데이터를 AI 모델 학습에 사용하지 않는다.
. AI Provider 계약 : Anthropic·OpenAI 등 외부 AI Provider 와의 계약에 "User 데이터 학습 미사용" 조항을 포함한다.
. 검증 방법 : 회사는 분기별로 AI Provider 데이터 처리 정책 변경 여부를 점검한다.

## 12.4 템플릿 마켓 라이선스

. 판매자 부여 라이선스 : 템플릿 판매자는 구매자에게 비독점적·전 세계적·영구적 사용 라이선스를 부여한다.
. 구매자 권리 : 구매자는 템플릿을 본인 프로젝트에 적용·수정·재사용할 수 있다.
. 구매자 제한 : 구매자는 템플릿 자체의 재판매 또는 마켓 재등록이 불가하다.
. 판매자 권리 유지 : 판매자는 동일 템플릿을 다른 구매자에게 추가 판매할 수 있다.
. 저작권 침해 처리 : 회사는 판매자 템플릿의 제3자 저작권 침해가 사후 확인된 경우 즉시 게시 중단·삭제 조치하고, 구매자에게 전액 환불한다. 환불액은 판매자가 부담한다.

## 12.5 회사 저작권 보호

. 회사 귀속 자산 : 서비스 UI·로고·디자인·소스 코드·AI Pipeline 알고리즘·이미지 워터마크의 저작권은 회사에 귀속된다.
. 금지 행위 : User 는 회사의 사전 서면 동의 없이 다음 행위를 할 수 없다.
  - 서비스 자체의 복제·배포
  - 서비스의 역설계 (Reverse Engineering)
  - 서비스 UI 의 모방 또는 스크린샷의 상업적 사용
  - Public API 및 MCP Server 를 활용한 동등 서비스 구축

# 13장. Public API 정책

## 13.1 API Key 발급·관리

. 발급 대상 : Pro·Team 등급
. 발급 방식 : User 가 [마이페이지 > API Key > 신규 발급] 클릭 시 평문 키 1회 표시 + 해시값 DB 저장
. Key 개수 제한 : Pro 5개, Team 10개
. Key 라벨링 : User 가 Key 별 이름을 부여하여 용도 구분 가능 (예: "production", "staging")
. 취소 절차 : User 가 [취소] 클릭 시 revoked_at 설정되며 즉시 무효화. 취소 후 grace period 없음.

## 13.2 Rate Limit

| 인증 유형 | 분당 호출 한도 | 초과 응답 |
|---|---|---|
| 비인증 (IP 기반) | 20회 | HTTP 429 + Retry-After 헤더 |
| 인증 User (Web App·Plugin) | 60회 | HTTP 429 + Retry-After 헤더 |
| Pro API Key | 300회 | HTTP 429 + Retry-After 헤더 |
| Team API Key | 600회 | HTTP 429 + Retry-After 헤더 |

. 응답 헤더 : 모든 응답에 X-RateLimit-Limit·X-RateLimit-Remaining·X-RateLimit-Reset 헤더를 포함한다.

## 13.3 API 남용 방지

. 비정상 패턴 감지 : System 이 짧은 시간 내 대량 호출·동일 IP 다중 키 호출·404 응답 비율 과다 등을 감지한 경우 해당 Key 의 호출을 자동 일시 차단한다.
. 차단 후 처리 : 차단 즉시 User 에게 인앱 + 이메일 알림 발송. 알림에 차단 사유와 해제 요청 절차를 포함한다.
. 해제 요청 : User 가 [서비스 내 차단 해제 신청 폼] 또는 운영 담당자 이메일로 요청. 운영자 검토 후 영업일 기준 3일 내 결과 통지.
단, 결제 사기·다중 계정·자동화 스크립트 남용 등 악의적 사용이 명백한 경우 영구 Key 회수 + 계정 정지 처리한다.
